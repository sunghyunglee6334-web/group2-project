## 0. 큰 틀 — 무엇을 지키려고 나누는가

| 우선순위 | 원칙 | 이유 |
|---|---|---|
| 1 | **누수 방지**: 같은 촬영 묶음은 같은 split | 같은 이물 세트가 Train과 Test에 같이 있으면 "이미 본 문제"를 맞히는 것이라 점수가 부풀려짐 |
| 2 | **장수 고정**: Train 600 / Val 75 / Test 75 / Bridge Holdout 150 | 팀 가이드 고정값. 오차 0장 (`size_tolerance = 0`) |
| 3 | **기존 validation 우선**: `original_split = validation` 사진을 Val 후보로 먼저 사용 | 원본 데이터셋이 정한 검증셋을 최대한 유지 |
| 4 | **구성 균형**: 각 split이 전체 900장과 비슷한 구성 | 장면 유형, Class 객체 비율, 배경 비율이 한쪽에 쏠리면 평가가 왜곡됨 |
| 5 | **학습 우선**: Train이 Class·배경을 가장 많이 가짐 | 모델이 배워야 평가도 의미가 있음 |

> 1·2는 절대 풀지 않는 조건, 4·5는 해가 없으면 정해진 순서대로 완화하는 조건이다.

**결정 흐름 (큰 틀 → 세부):**

```
[1단계] 묶음 만들기 (누수 방지)
   └ [2단계] 묶음마다 속성 계산 (무엇을 비교할지)
        └ [3-0] Val 먼저: 기존 validation 사진으로 Val 75장
             └ [3단계] 남은 묶음에서 Bridge 150 → Test 75, 나머지 Train
                  └ 필수 조건 확인 → 안 되면 완화 사다리
                       └ [4단계] 검증 → [5단계] 저장
```

## 1단계. 누수 방지 그룹 — "무엇을 한 덩어리로 볼 것인가"

### 근거
- 촬영 방식(촬영자 확인):
  - 같은 이물 세트를 김치 위에서 **옮겨 가며** 찍었다.
  - 25장마다 김치 종류(파 → 고추 등)가 바뀌지만, **이물은 그대로**다.
  - **5분 넘게 쉴 때 이물을 바꿨다.** 이물은 날짜마다 조금씩 다르다.
- 결론: 그룹 경계는 25장 블록이 아니라 **5분 이상 쉰 시점**이다.

### 세부 조건

| 단계 | 조건 | 값 | 근거 |
|---|---|---|---|
| 1-1 | 촬영 시각 순 정렬 | 파일명 `YYMMDD_HHMMSSffffff` | 파일명에 촬영 시각이 들어 있음 |
| 1-2 | 인접 사진 간격 Δt가 기준을 넘으면 새 그룹 (`time_group`) | `GAP_SECONDS = 300` (5분) | 쉬는 동안 이물이 바뀜 → **18개 묶음 T00~T17** |
| 1-3 | 같은 파일(MD5)이 다른 묶음에 있으면 두 묶음 병합 | `use_md5 = True` | 완전 중복은 무조건 같은 그룹 |
| 1-3 | 거의 같은 사진(pHash)이 다른 묶음에 있으면 병합 | 거리 ≤ 5 | 시간이 떨어져도 같은 장면이면 누수. imagehash 설치 시 동작 |
| 1-4 | 그룹 크기 확인 | 전체의 20% 초과 시 경고 | 한 그룹이 너무 크면 배정 조합이 막힘 |

- 25장 블록은 그룹 경계로 쓰지 않고 참고 정보로만 남긴다.

## 2단계. 그룹 속성 — "묶음끼리 무엇을 비교할 것인가"

사진 한 장이 아니라 **묶음 단위**로 계산한다. 배정도 묶음 단위로 하기 때문이다.

| 단계 | 속성 | 계산 | 쓰는 곳 |
|---|---|---|---|
| 2-1 | 장면 유형 (`scene_mode`) | 묶음 안 `scene_type` 최빈값 + 장면별 이미지 수 | 층 나누기, 장면 비율 점수 |
| 2-2 | 클래스 다양성 (`diversity`) | 묶음에 나온 Class의 합집합 개수 → 0 / 1-2 / 3-4 / 5-6 | 층 나누기 (세훈님 분류 아이디어) |
| 2-3 | 희소 Class 포함 (`has_rare`) | Class 6 포함 여부 | Train 보호 |
| 2-4 | 객체 수, 배경 수 | Class별 bbox 수, 빈 라벨 이미지 수·비율 | Class 비율 점수, 배경 조건 |
| 2-4 | 출처 (`d1`) | Dataset1 이미지 수 | 출처 비율 조건 |
| 2-4 | 애매한 라벨 (`ambiguous`) | `issue`/`note`에 모호·ambiguous·불확실·의심·REVIEW 포함 | 평가셋 품질 조건 |
| 2-4 | 촬영 날짜 (`dates`) | 묶음의 날짜 목록 | 날짜 다양성 조건 |
| 2-5 | 기존 validation 수 (`orig_val`) | `original_split = validation` 수 | Val 먼저 |

- **층 (stratum) = 장면 유형 × 클래스 다양성** — 예: `kimchi_with_target|5-6`

### 전체 900장의 구성 (기준값)

| 항목 | 값 |
|---|---|
| 장면 | 김치+이물 725 · 이물만 151 · 정상 김치 24 |
| 배경(빈 라벨) | 26장 |
| 출처 | Dataset1 500 (55.6%) / Dataset2 400 |
| 애매한 라벨 | 28장 |
| 날짜 | 04-10 150 · 04-11 250 · 04-24 350 · 05-13 150 |
| Class | 4는 0개 (고무장갑 → Class 1로 합침), 6은 약 96%가 T00에 몰림 |

## 3-0단계. Val 먼저 — "기존 validation으로 Val 75장 만들기"

### 근거
- 원본 validation 180장은 한 묶음에 몰려 있지 않고 **묶음마다 14~30%씩 흩어져** 있다.
- 묶음째로만 배정하면 기존 validation을 Val로 살릴 수 없다.
- 그래서 Val에 한해 **묶음을 쪼개는 예외**를 둔다.

### 세부 조건

| 단계 | 조건 | 값 | 근거 |
|---|---|---|---|
| 3-0-1 | 묶음마다 기존 validation 사진만 모아 **V 조각**(`Txx_V`)을 만든다 | — | 사진 단위가 아닌 묶음별 조각으로 관리 |
| 3-0-2 | V 조각 조합으로 정확히 75장 | 최대 6조각 | 장수 고정 |
| 3-0-2 | Val 조건 통과 | 애매한 라벨 ≤ 1, 날짜 ≥ 1, 출처 조건 없음 | 기존 validation만 쓰면 출처를 맞출 수 없음 |
| 3-0-2 | 구성 점수 + 조각 수 벌점 | 조각당 0.05 | 쪼개는 묶음이 적을수록 좋음 |
| 3-0-3 | 조각을 내준 묶음의 나머지(`Txx_R`)는 **Train 고정** | — | Test·Bridge에 Val과 같은 이물 세트가 들어가지 않게 |
| 3-0-3 | 점수 상위 60개 Val 후보마다 Bridge·Test를 배정해 보고, 전체 점수가 가장 좋은 것 선택 | `top_k = 60` | Val만 좋고 나머지가 나쁜 배정 방지 |
| 표시 | 쪼갠 사진에 `same_bundle_split = True` | — | **Val 점수는 실제보다 좋게 나올 수 있음** |

## 3단계. Bridge·Test·Train 배정 — "남은 묶음을 어떻게 나눌 것인가"

### 3-1. 비교 기준
- 전체 900장의 층·장면·Class 객체·배경 비율을 기준으로 둔다.

### 3-2. Train 보호 (다른 split으로 보내지 않음)

| 조건 | 값 | 근거 |
|---|---|---|
| 직접 고정 | `pinned_train` | 팀이 정한 예외 |
| 이물만 사진이 절반 이상인 묶음 | ≥ 50% | Train에도 이물만 사진이 있어야 함 |
| 층에 묶음이 하나뿐 | — | 빼면 Train에서 그 층이 사라짐 |
| 희소 Class 6 이미지를 많이 가진 묶음 | ≥ 40% | 희소 Class는 학습이 먼저 → **T00 고정** |

### 3-3. 역할별 필수 조건 (Hard)

| 조건 | Bridge 150 | Test 75 | Val 75 | Train 600 |
|---|---|---|---|---|
| 장수 | 정확히 | 정확히 | 정확히 | 나머지 |
| 묶음째 배정 | ✔ (손대지 않은 묶음만) | ✔ (손대지 않은 묶음만) | V 조각 | 나머지 + `_R` |
| 애매한 라벨 | ≤ 1 | ≤ 1 | ≤ 1 | — |
| 날짜 수 | ≥ 2 | ≥ 2 | ≥ 1 | — |
| 출처(Dataset1) 비율 | 55.6 ± 10%p | 55.6 ± 10%p | — | 55.6 ± 10%p |
| Train에 모든 층 1개 이상 | | | | ✔ |

**근거**
- 날짜 ≥ 2: 하루치만 있으면 그날의 조명·이물에 점수가 좌우된다.
- 애매한 라벨 ≤ 1: 평가셋은 정답이 확실해야 한다.
- 출처 ±10%p: 두 데이터셋의 촬영 조건 차이가 점수에 섞이지 않게 한다.

### 3-3. 균형 조건 (해가 없으면 완화)

| 조건 | 기본값 | 근거 |
|---|---|---|
| Val·Test에 평가 Class(0,1,2,3,5)별 최소 객체 | 각 5개 | Class별 AP를 계산하려면 최소한은 있어야 함 |
| 배경 이미지 중 Train 비율 | ≥ 50% | 배경으로 오탐 억제를 학습 |
| Train Class 객체 수가 다른 split보다 많음 | 평가 Class마다 | 학습 데이터가 가장 많아야 함 |

### 3-3. 고르는 방법 (점수)
- 조건을 통과한 조합 중 **전체 구성과의 차이 합이 가장 작은 배정**을 고른다.

| 항목 | 계산 | 가중치 |
|---|---|---|
| 층 | 층별 이미지 비율 차이 (L1) | 0.5 |
| 장면 | 장면별 이미지 비율 차이 (L1) | 1.0 |
| Class | Class별 객체 비율 차이 (L1) | 1.0 |
| 배경 | 배경 비율 차이 × 10 | 1.0 |

- 탐색 방식:
  - 무작위 seed가 아니라 **모든 조합을 따져 보는 결정적 탐색**이다(분기 한정).
  - 그래서 누가 실행해도 같은 결과가 나온다.
  - 근거: seed 0~1999 무작위로는 해를 못 찾았다.
- 배정 순서: Bridge → Test (Val은 3-0에서 이미 정함). 가장 엄격한 역할부터 정한다.

### 3-3. 완화 사다리
- 모든 조건을 만족하는 배정이 없으면 아래 순서로 하나씩 풀고 다시 찾는다. 풀린 조건은 리포트에 기록한다.

| 순서 | 완화 내용 |
|---|---|
| ① | Val·Test Class별 최소 객체 수 해제 |
| ② | 배경 Train 비율 50% → 30% |
| ③ | Train Class 객체 최다 조건 해제 |
| ④ | 배경 Train 비율 조건 해제 |

- 장수, 날짜, 애매한 라벨, 출처 비율은 **절대 풀지 않는다.**
- 이번 실행에서는 ①~③까지 3개를 완화했다. 사진 수가 적고 묶음이 18개뿐이라 모든 조건을 동시에 만족할 수 없었다.

## 6. 알려진 한계와 남은 결정

| 한계 | 영향 | 대응 |
|---|---|---|
| Val은 Train과 같은 묶음에서 쪼갬 (180장 중 135장이 Train 사진과 60초 이내) | Val 점수가 낙관적 | Val은 모델 선택용, **최종 성능은 Test 기준** |
| Val의 Dataset1 0% | Val은 Dataset2 조건만 반영 | PM 공유 |
| Test·Bridge에 정상 김치·이물만 사진 없음 | 깨끗한 김치에서의 오탐률을 잴 수 없음 | A: 한계로 기록 / B: T02를 Val로 옮겨 85장 (PM 결정) |
| Split마다 Class 비율 차이가 큼 | Class별 AP 편차 | 허용 범위 설정 / K-Fold / 한계 기록 (검토 중) |
| pHash 병합 미실행 | 시간이 떨어진 유사 사진 누수 가능성 | imagehash 설치 후 재실행 |
