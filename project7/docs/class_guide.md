# Class Labeling Guide

- 문서 버전: v1.7.1
- 작성일: 2026-10-06
- 마지막 수정일: 2026-10-13
- 담당: Coord
- 원본 위치: Git `docs/class_guide.md` (팀 노션 원본과 같은 내용)

> 이 문서는 이미지 안의 객체를 **어떤 Class로 지정할지** 정한 팀 공통 기준입니다.
> BBox를 어디까지 그릴지는 `docs/bbox_guide.md`를 따릅니다.

---

## 공통 원칙

1. 사용 Class는 **0~6**이며, Class 번호와 이름은 `configs/classes.yaml`과 항상 같게 유지한다.
2. **판단이 명확한 객체만** 해당 Class로 지정한다.
3. Class 판단이 어려우면 임의로 정하지 않고 **REVIEW**로 처리한다.
4. **김치 자체는 검출 대상 Class가 아니다.** (김치 잎, 김치 조각, 양념은 BBox를 만들지 않는다.) 김치는 **배경**으로 학습된다. 즉 BBox가 없는 김치 영역을 모델이 "이물이 아닌 정상"으로 배운다. 그래서 김치에 BBox가 남아 있으면 모델이 김치를 이물로 배우게 되므로 반드시 지운다.
5. **고무장갑은 Class로 분류하지 않는다.** 고무장갑에는 BBox를 만들지 않으며, Class 4도 사용하지 않는다. (아래 Class 4 참고)
6. 눈에 보이는 특징(모양, 색, 재질)을 근거로 판단한다. "아마 ~일 것이다"라는 추측으로 정하지 않는다.
7. 하나의 객체에는 하나의 Class만 지정한다.
8. 기존 라벨이 이 문서와 다르게 표기되어 있으면 이 문서 기준으로 고치고 `EDITED`로 기록한다. (아래 "기존 라벨 오표기 수정" 참고)
9. 이 문서에 없는 사례는 혼자 정하지 않고 서기를 통해 결정 로그에 올린 뒤 이 문서에 반영한다.
10. **작아도 이물이 확실하면 BBox를 그린다.** 학습 해상도(imgsz)에서 잡히지 않을 것 같다는 이유로 라벨을 빼지 않는다. (아래 "작은 이물 처리 기준" 참고)

## Class 0 — 나뭇잎·종이류

**대상**
조각김치 사이에서 발견되는 나뭇잎 또는 종이 형태의 객체

**포함**

- 활엽수 잎
- 잘린 잎 조각
- 종이 조각
- 꽃

**제외**

- 배추 잎
- 파
- 고추

**애매한 경우 → REVIEW**

- 나뭇잎인지 배추 잎인지 명확하지 않을 때

**구분 기준:** 침엽수 잎(솔잎)과 솔방울은 나뭇가지(Class 2)로 본다.

---

## Class 1 — 플라스틱류·돌·금속류

**대상**
플라스틱, 돌, 금속과 같이 제조 과정에서 이물로 판단되는 객체

**포함**

- 플라스틱 조각
- 돌
- 금속 조각
- **빨간색 노끈 (확정)**
- 스티로폼
- **스티로폼 알갱이 (확정)** — 작은 흰색 알갱이라도 스티로폼이 확실하면 BBox + Class 1, 노트에 `small`. 스티로폼은 플라스틱 종류이므로 Class 1로 한다.

**제외**

- **고무장갑** (Class 분류 안 함, BBox를 만들지 않는다)
- 나뭇가지
- **나무껍질 같은 넓은 갈색 물체** (기존 라벨에 플라스틱(Class 1)으로 표기된 경우가 있으나 **Class 2** 로 한다)
- 식물성 잎
- 파·고추

**애매한 경우 → REVIEW**

- 재질을 이미지로 판단하기 어려울 때
- 너무 작아서 점·얼룩인지 이물인지 판단할 수 없을 때 (사유: `대상 크기 작음`)

---

## Class 2 — 나뭇가지류

**대상**
막대 또는 가지 형태의 나무성 이물, 그리고 이와 같은 나무 계열 이물

**포함**

- 나뭇가지, 작은 가지 조각
- **솔잎** (나뭇잎이지만 가늘고 긴 형태 때문에 나뭇가지로 분류한다)
- **잎사귀 없이 줄기만 존재하는 것**
- 줄기 형태의 목질
- **솔방울**
- 잎이 달린 가지
- 나무껍질

**제외**

- 파 줄기
- 고추 꼭지
- 일반 잎 조각 (→ Class 0)

**애매한 경우 → REVIEW**

- 나뭇가지와 채소 줄기의 구분이 어려울 때
- 나무껍질과 플라스틱의 구분이 어려울 때

---

## Class 3 — 벌레류

**대상**
이미지에서 확인되는 벌레 또는 곤충 형태의 객체

**포함**

- 벌레
- 곤충 형태가 명확한 객체

**제외**

- 작은 검은 반점
- 형태를 식별할 수 없는 이물

**애매한 경우 → REVIEW**

- 벌레인지 단순 얼룩인지 판단하기 어려울 때

---

## Class 4 — 고무장갑 (사용 안 함)

**현재 사용 여부**
사용하지 않음. **고무장갑은 어떤 Class로도 분류하지 않는다.**

**처리 기준**

- 고무장갑에는 **BBox를 만들지 않는다.** (Class 4도, Class 1도 쓰지 않는다)
- 기존 TXT에 고무장갑 BBox가 있으면(Class 4든, 이전 기준에 따른 Class 1이든) **BBox를 삭제하고 `EDITED`** 로 기록한다. 이미지는 제외하지 않고 데이터셋에 유지한다.
- 고무장갑 BBox를 삭제한 경우 노트에 무엇을 지웠는지 적는다. (예: `#2 삭제, 고무장갑`)
- **김치와 고무장갑만 있는 사진은 장면 유형을 "정상 김치"로 고른다.** (빈 TXT가 정상)
- 고무장갑과 다른 이물이 함께 있으면 다른 이물에만 BBox를 그리고, 장면 유형은 "김치 + 대상 객체"로 고른다.
- 최종 `data/final/`의 라벨에는 Class 4가 남아 있으면 안 된다. (Validation에서 확인)

---

## Class 5 — 병해·갈변

**대상**
식재료에서 확인되는 병해 또는 갈변 형태

**포함**

- 갈색으로 변색된 부위
- **병해로 판단되는 이상 부위(검은색 반점) [회의 필요 — 점박이 병해를 모두 제외할지 여부]**

> 예시 사진은 팀 노션 원본에 있습니다. (실제 데이터 사진은 Git 에 올리지 않습니다)

**제외**

- 그림자
- 촬영 조명에 의한 색 변화

**애매한 경우 → REVIEW**

- 실제 갈변인지 조명 차이인지 판단하기 어려울 때

---

## Class 6 — 파·고추

**대상**
조각김치 이미지에서 검출 대상으로 지정된 파 또는 고추

**포함**

- 파 조각
- 고추 조각

**제외**

- 김치 잎
- 나뭇잎
- 나뭇가지

**애매한 경우 → REVIEW**

- 파·고추와 다른 식물 조각을 구분하기 어려울 때

---

## 작은 이물 처리 기준

**결론: 작아도 잡는다.** 작은 흰색 스티로폼처럼 크기가 작아도 이물이 확실하면 BBox를 그린다. (`docs/bbox_guide.md` 4장: "작더라도 Class를 식별할 수 있고 검출 대상이면 BBox를 작성합니다.")

### 최종검수 처리표

| 상황 | 처리 | 검수 결과 |
| --- | --- | --- |
| 작지만 이물(예: 스티로폼)이 확실함 | BBox + 해당 Class (스티로폼은 Class 1) · 노트에 `small` | 검수 완료 |
| 너무 작아서 점·얼룩인지 이물인지 모르겠음 | REVIEW + 사유 `대상 크기 작음`(too_small_to_identify) | 확인 필요 |
| 3px보다 작음 | 라벨링 프로그램이 박스를 만들지 않음 (실수 드래그 방지) | - |

### `small` 노트를 적는 이유

교과 8 실패분석 때 "작은 이물 FN"을 노트로 바로 골라낼 수 있다. 이 목록이 개선 실험(imgsz 올리기)의 근거가 된다.

### "어차피 학습에서 안 잡히니까 빼자"가 손해인 이유

1. **빼면 모델이 "배경"으로 배운다.** 라벨이 없는 스티로폼은 정상 김치로 학습된다. 그러면 나중에 해상도를 올려도 잡히지 않는다.
2. **해상도 올리기가 교과 8의 개선 실험이다.** imgsz 640에서는 놓치고 960·1280에서 잡히면 "작은 이물 FN이 줄었다"가 실험 결과가 된다. 라벨이 있어야 이 비교를 할 수 있다.
3. **기준이 흔들리면 안 된다.** BBox 기준서 4장에 이미 정해져 있다. 학습 해상도에 맞춰 기준을 바꾸면 앞서 검수한 520장과 기준이 달라진다.
4. **이물검출은 놓치는 게 가장 위험하다(Recall).** 현장에서는 작은 스티로폼도 불량이다.

## 기존 라벨 오표기 수정

기존 데이터에서 아래처럼 잘못 표기된 라벨이 확인되었다. 발견하면 올바르게 고치고 `status = EDITED`로 기록한다.

| 대상 객체 | 기존 표기 | 올바른 처리 | 처리 |
| --- | --- | --- | --- |
| 나무껍질 같은 넓은 갈색 물체 | Class 1 (플라스틱류) | **Class 2** (나뭇가지류) | Class 수정 → EDITED |
| 고무장갑 | Class 4 또는 Class 1 | **BBox 삭제** (Class 분류 안 함) | BBox 삭제 → EDITED |
| 빨간색 노끈 | Class 1이 아닌 다른 Class 또는 라벨 없음 | **Class 1** | Class 수정 또는 BBox 추가 → EDITED |
| 작은 스티로폼 알갱이 | 라벨 없음 (BBox 누락) | **Class 1** + 노트 `small` | BBox 추가 → EDITED |
| 김치 잎 · 김치 조각 · 양념 | 아무 Class 로 BBox 가 있음 | **BBox 삭제** (김치 = 배경) | BBox 삭제 → EDITED, 노트 `#n 삭제, 김치` |

## 헷갈리기 쉬운 Class 구분표

작업하다 판단이 갈린 사례는 이 표의 마지막 칸에 계속 추가한다.

| 헷갈리는 쌍 | 판단 포인트 | 확정된 기준 / 사례 |
| --- | --- | --- |
| 고무장갑 ↔ 플라스틱류(1) | 고무장갑을 이물 Class로 볼 것인가 | **확정:** 고무장갑은 **Class 분류 안 함**, BBox 없음. 김치 + 고무장갑만 있으면 장면 유형 "정상 김치" |
| 빨간색 노끈(1) ↔ 고추(6) | 붉은색이지만 가늘고 꼬인 끈 형태인가 | **확정:** 빨간색 노끈 → **Class 1** |
| 스티로폼·작은 알갱이(1) ↔ 라벨링 제외 | 너무 작아 식별하기 어려운 알갱이도 이물로 볼 것인가 | **확정:** 스티로폼이 확실하면 작아도 **Class 1** + 노트 `small`. 점·얼룩과 구분이 안 되면 REVIEW(`대상 크기 작음`) |
| **병해 점박이(5) ↔ 얼룩·반점·양념(제외)** | **검은 점박이 병해를 모두 버릴 것인가, 일부만 남길 것인가** | **[회의 필요] 전부 제외 여부** |
| 솔방울(2) ↔ 나뭇잎(0)·기타 | 솔방울은 잎이 아니라 나무성 이물로 본다 | 솔방울 → **Class 2** (확정, REVIEW 없음) |
| 솔잎(2) ↔ 나뭇잎(0) | 솔잎은 잎이지만 가늘고 긴 형태라 나뭇가지류로 본다 | 솔잎 → **Class 2** (확정) |
| 나무껍질(2) ↔ 플라스틱(1) | 넓은 갈색 나무성 물체는 나무껍질로 본다 | 나무껍질 → Class 2 |
| 김치 잎(배경) ↔ 나뭇잎(0) · 병해(5) | 김치(배추) 자체인가, 김치 위에 있는 별도 이물인가 | **확정:** 김치 자체는 BBox 없음(배경). 배추 잎인지 나뭇잎인지 모르면 REVIEW |

## Class 판단 순서

```
객체 발견
    ↓
검출 대상인가? (김치 자체·양념·고무장갑은 대상 아님 → BBox 안 만듦)
    ↓
후보 Class 찾기 → "포함" 목록과 일치?
    ↓
"제외" 목록에 해당하지 않는가?
    ↓
명확함 → Class 지정 → 저장
```

```
후보가 둘 이상이거나 포함·제외 모두에 걸림
    ↓
임의로 Class 지정하지 않음
    ↓
REVIEW + 사유 기록 (class_ambiguous)
    ↓
교차검수자 + PM 최종 판단
    ↓
결정 로그 기록 → 구분표와 이 문서 개정
```

```
고무장갑 발견 (또는 기존 Class 4 / Class 1로 표기된 고무장갑)
    ↓
BBox 만들지 않음 (기존 BBox는 삭제 → EDITED, 노트에 기록)
    ↓
사진에 다른 이물이 있는가?
    ├─ 없음(김치 + 고무장갑만) → 장면 유형 "정상 김치" (빈 TXT)
    └─ 있음 → 다른 이물에만 BBox, 장면 유형 "김치 + 대상 객체"
```

```
작은 객체 발견
    ↓
3px보다 작은가? → 예: 박스 안 만들어짐
    ↓ 아니오
이물(Class)이 확실한가?
    ├─ 예  → BBox + Class 지정 + 노트 small → 검수 완료
    └─ 아니오(점·얼룩인지 모름) → 확인 필요 + 대상 크기 작음
```

## 장면 유형 (Scene Type)

장면 유형은 **사진 전체가 어떤 모습인지** 고르는 칸입니다. Class(박스 종류)와는 다른 것이고, Manifest의 `scene_type` 칸에 저장됩니다.
교과 8에서 "정상 김치 몇 장, 이물 섞인 김치 몇 장"을 세는 데 쓰이고, QA Summary와 Handoff 산출물에도 들어갑니다.
그래서 **검수하면서 한 장씩 꼭 골라 주는 것**이 좋습니다.

| 선택 | 언제 | 박스 |
| --- | --- | --- |
| 김치 + 대상 객체 | 김치 사이에 이물(나뭇잎, 벌레, 파·고추 등)이 있음 | 이물에 박스 있음 |
| 정상 김치 | 김치만 있고 이물이 없음 / **김치와 고무장갑만 있음** | 박스 0개 (빈 TXT가 정상) |
| 대상 객체 단독 | 김치 없이 이물만 단순한 배경에 놓여 있음 | 이물에 박스 있음 |
| 판단 어려움 | 위 셋 중 뭔지 애매함 | 검수 상태도 "확인 필요" + 메모 |
| 선택 안 함 | 아직 안 고름 | ❌ 검수 완료 전에 꼭 바꾸기 |

> 작은 스티로폼 하나라도 이물이 확실해 박스를 그렸다면 "정상 김치"가 아니라 **"김치 + 대상 객체"** 입니다.
> 고무장갑은 박스를 그리지 않으므로, 김치와 고무장갑만 있으면 **"정상 김치"** 입니다.

## 검수 결과 저장 기준

검수자는 고쳤든 안 고쳤든, **확실하면 "검수 완료"로 저장**합니다. **애매한 것만 "확인 필요"로 남깁니다.**

| 검수 결과 | 누를 버튼 | 노트 |
| --- | --- | --- |
| 그대로 맞음 | **검수 완료** | 비워도 됨 |
| 내가 고쳤고, 고친 게 확실함 | **검수 완료** | ✅ **무엇을 고쳤는지 꼭** (예: `#5 삭제, 배추 조각`) |
| 고무장갑 BBox를 삭제함 | **검수 완료** | ✅ `#2 삭제, 고무장갑` |
| 작지만 이물이 확실함 | **검수 완료** | ✅ `small` (예: `#3 추가, 스티로폼 small`) |
| 애매함 · 빈 TXT 판단 · 너무 작아 식별 불가 | **확인 필요** | ✅ 이유 |

## REVIEW(확인필요) 사유 코드 (Class 관련)

| 코드 수정 전 (영문) | 코드 수정 후 (한글) | 의미 |
| --- | --- | --- |
| class_ambiguous | class 모호함 | 후보 Class가 둘 이상이거나 포함·제외 기준으로 판단하기 어려움<br>ex) #0 : class 1 또는 2 |
| class4_found | class4 고무장갑 | **v1.7부터 사용 안 함.** 고무장갑은 REVIEW 없이 BBox를 삭제한다 |
| not_target_maybe | 검출 대상 불확실 | 검출 대상인지 자체가 불확실 |
| too_small_to_identify | 대상 크기 작음 | 너무 작아 점·얼룩인지 이물인지 식별 불가 (식별되면 REVIEW가 아니라 BBox + `small`) |
| other | 기타 | 기타 (메모에 이유 기록) |

BBox 범위·객체 구분에 관한 사유 코드는 `docs/bbox_guide.md`를 따른다.

### 노트 태그 (REVIEW 사유 아님)

| 태그 | 의미 | 쓰임 |
| --- | --- | --- |
| `small` | 작지만 식별 가능한 이물에 BBox를 그림 | 교과 8 실패분석에서 "작은 이물 FN"을 골라내 imgsz 개선 실험 근거로 사용 |

## 저장 전 확인 체크

- [ ] Class 번호가 이 문서의 표(0~6)와 맞다
- [ ] Class 4가 남아 있지 않고, 고무장갑에 BBox가 없다
- [ ] 빨간색 노끈은 Class 1로 표기했다
- [ ] 김치 자체에 BBox를 만들지 않았다
- [ ] 작아도 이물이 확실한 객체(예: 스티로폼 알갱이)에 BBox를 그렸고 노트에 `small`을 적었다
- [ ] 판단이 어려운 객체는 REVIEW로 표시하고 `note`에 사유를 적었다
- [ ] 장면 유형을 골랐다 ("선택 안 함"으로 남아 있지 않다). 김치 + 고무장갑만 있으면 "정상 김치"다
- [ ] 확실한 것은 "검수 완료", 애매한 것(빈 TXT 판단 포함)만 "확인 필요"로 저장했고, 고친 경우 노트에 무엇을 고쳤는지 적었다
- [ ] 저장 후 Validation 오류가 없다
